# Reproducibility Guide

This document provides step-by-step instructions to fully reproduce the extraction, preprocessing, and statistical analysis presented in:

> *Spatiotemporal Dynamics and Hotspot Analysis of Atmospheric Pollutants in Nepal Using Sentinel-5P and Google Earth Engine (2019–2026)*

## Phase 1: Data Extraction (Google Earth Engine)

All raw satellite data is extracted using Google Earth Engine (GEE) JavaScript Code Editor scripts.

1. Create a free Google Earth Engine account at [earthengine.google.com](https://earthengine.google.com).
2. Open the GEE Code Editor.
3. Copy the contents of each script in the `gee_scripts/` directory into the Code Editor.
   - `01_no2_extraction.js` through `06_uvai_extraction.js` extract the core Sentinel-5P TROPOMI data.
   - `07_era5_climate_extraction.js` extracts meteorological drivers.
   - `08_landcover_extraction.js` to `10_sentinel2_ndvi_extraction.js` extract demographic and geographic context.
4. Run each script.
5. Go to the **Tasks** tab in the GEE Code Editor and click **Run** for each export task.
6. The data will be exported to your Google Drive in a folder named `GEE_Exports` as CSV files.
7. Download these CSV files and place them in the `data/raw/` directory of this repository.

> [!NOTE]
> All GEE scripts use explicit Coordinate Reference Systems (`EPSG:4326`) and standardized `scale` parameters in their `reduceRegion` calls to ensure geometric reproducibility.

## Phase 2: Python Environment Setup

The analytical pipeline is written in Python 3.12+.

1. Open your terminal in the repository root.
2. Create a virtual environment:
   ```bash
   python -m venv venv
   ```
3. Activate the virtual environment:
   - Windows: `venv\Scripts\activate`
   - Mac/Linux: `source venv/bin/activate`
4. Install the exact dependencies required for this analysis:
   ```bash
   pip install -r requirements.txt
   ```

## Phase 3: Analytical Pipeline Execution

The Python scripts are designed to be run sequentially. They process the raw data, perform statistical tests (e.g., Mann-Kendall, Sen's Slope, STL Decomposition), and generate the publication-ready figures.

1. **Pre-processing:**
   ```bash
   python analysis/01_data_preprocessing.py
   ```
   *This aligns timestamps, imputes missing data (if any), and saves clean files to `data/processed/`.*

2. **Core Statistics & Trends:**
   ```bash
   python analysis/02_descriptive_statistics.py
   python analysis/03_trend_analysis.py
   python analysis/04_stl_decomposition.py
   python analysis/11_breakpoint_analysis.py
   ```

3. **Spatial & Thematic Analyses:**
   ```bash
   python analysis/05_spatial_statistics.py
   python analysis/06_emerging_hotspot.py
   python analysis/10_population_exposure.py
   python analysis/12_covid_lockdown_analysis.py
   ```

4. **Meteorological Correlation:**
   ```bash
   python analysis/07_climate_correlation.py
   python analysis/08_wavelet_analysis.py
   python analysis/09_granger_causality.py
   python analysis/13_era5_meteorological_analysis.py
   ```

5. **Internal Validation:**
   ```bash
   python analysis/14_validation_proxy.py
   ```

## Phase 4: Figure Generation

All figures and tables generated by the scripts above are automatically saved to the `figures/` directory and its subdirectories (`covid_analysis/`, `era5_analysis/`, `trend_analysis/`, `validation/`). 
- **.png files** are generated at 300 DPI for standard viewing.
- **.pdf files** are generated as vector graphics, suitable for direct submission to high-impact journals.

## Troubleshooting

- **Missing Data Errors:** If a Python script fails due to a missing CSV, ensure that the GEE export task completed successfully and the file was moved exactly to `data/raw/`.
- **Package Version Conflicts:** Always use the pinned versions in `requirements.txt`. Changes to `pandas` or `statsmodels` behavior in future versions could alter statistical outputs.
